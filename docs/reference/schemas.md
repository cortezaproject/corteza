# Schemas

The shape of each resource a configurator writes, as [JSON Schema](https://json-schema.org/),
generated from the types the server stores. Field and property names are the
ones the REST API and the MCP tools accept; closed lists (field kinds, block
kinds) are enumerated.

| Schema                                                                    | Describes                                                                                                                     |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| [module.schema.json](/schemas/module.schema.json)                         | A module and its fields. `fields[].kind` is the closed list of field kinds; `fields[].options` depends on the kind.           |
| [page.schema.json](/schemas/page.schema.json)                             | A page: what its blocks are. A record page sets `moduleID`.                                                                   |
| [page-layout.schema.json](/schemas/page-layout.schema.json)               | One arrangement of a page's blocks on the 48-column grid, with the visibility condition that selects it.                      |
| [page-block-options.schema.json](/schemas/page-block-options.schema.json) | The `options` object of every block kind, keyed by kind, with the options a block cannot render without listed as `required`. |
| [chart.schema.json](/schemas/chart.schema.json)                           | A chart and its `config.reports[]`.                                                                                           |
| [taq.schema.json](/schemas/taq.schema.json)                               | A TAQ definition: triggers, steps and the paths between them.                                                                 |

What a schema cannot say is written next to it: per-kind field options and
chart metric and dimension entries are open objects whose keys the MCP skills
(`module_building`, `chart_building`) and the [TAQ reference](/reference/taq/steps)
list. IDs are 64-bit integers carried as strings everywhere.

The files are regenerated by `make docs-reference` in `server/` and a test fails
when they drift from the types.
