## 0. 强制执行规则

1. PR #3 只作为契约基线合入，不视为业务功能完成，也不视为后端 API、种子、真实 403 或外部 fixture 已验收。
2. 页面只能调用统一 `C311Provider`/adapter；禁止在页面、组件或测试中直接 `fetch` 业务 API，禁止为单个页面创建私有协议或临时 mock。
3. 每次新增或变更 provider 方法，必须同时提交 DTO/枚举、版本化 fixture、错误场景和 adapter contract test，并指定唯一维护者。
4. 前端的 capability、按钮隐藏和路由守卫只能改善 UX；最终授权必须由服务端独立执行。
5. 每个 PR 必须列出稳定条款编号、实现文件、单元/组件/E2E 测试、fixture 或真实环境说明、截图/日志、已知阻塞项，并执行：

   ```text
   git diff --check
   git status --short
   ```

## 1. PR #3 合入后的强制前置：FE-00-GATE

FE-00-GATE 不是业务功能 PR，可以作为独立的契约骨架/测试 fixture PR，也可以作为 FE-01 的第一个前置 commit。未通过前，不得开始 FE-01 的功能实现。

### 必须完成

- 记录 Corteza 基线启动、登录、记录、附件、历史、权限和刷新行为，形成基线清单和已知差异。
- 完成公共端、员工端、管理端、报表端、工作流端的页面、路由和权限入口盘点。
- 确认现有组件、状态管理、API client、locale、构建和测试约定；不得引入一次性架构。
- 固定统一 adapter、共享类型、契约版本和 mock provider 入口；页面不得依赖数据库字段或外部 fixture 细节。
- 建立每个数据区域的八类状态：`loading`、`empty`、`populated`、`forbidden`、`not-found`、`validation-error`、`retryable-error`、`terminal-error`。
- 建立角色与范围 fixture：`public_visitor`、`constituent`、`service_agent`、`supervisor`、`department_manager`、`platform_administrator`、`workflow_designer`；需要 API 验证时另备 `integration_client`。
- 每个角色 fixture 必须包含当前用户、部门/地区范围、capability、scope、可用路由和会话过期样例；不能只复用默认选民会话。
- 固定浏览器和视口测试表、EN/ES/VI 目录、英文回退、语言持久化、`America/New_York` 时间格式工具，以及成功、空、401、403、404、422、可重试、终止、409 的 fixture。
- 建立页面/条款追踪表，并把第 14.1.1 表的公共操作映射到后续 FE PR。

### FE-00-GATE 退出条件

1. Mock provider 能在不依赖真实业务后端的情况下展示成功、空、无权限、未找到、校验、可重试和终止错误。
2. 七类浏览器角色可以驱动路由守卫和 capability 测试，跨范围访问有可读的拒绝状态。
3. 所有后续页面只依赖统一 adapter，组件中不存在散落的接口字段拼接。
4. G1 Mock 冻结记录已提交；未确认字段、状态或错误必须标记为 `provisional`，不得伪装成最终契约。

## 2. 共享 adapter 与 fixture 规则

- FE-02～FE-09 按功能扩展 `C311Provider`，覆盖关系/备注/提醒、品牌/内容/帮助、身份/密码、邮件/ICS、审计、报表和数据导出等接口；扩展必须先更新共享类型和 fixture，再写页面。
- Mock 与真实 API 使用相同请求/响应形状；真实 API 接入时只替换 adapter，不重写页面。
- 每个错误 fixture 必须包含 HTTP 状态、稳定错误码、用户消息、`retryable` 和适用的字段/版本/失败记录信息。
- 需要服务器副作用的场景，Mock 只模拟可观察结果；不得把 Mock 通过当作持久化、权限、幂等、审计或外部系统已通过。

## 3. 前端 PR 顺序与执行内容

### FE-01：共享前端基础

实现公共端和员工端应用壳、主导航、路由守卫、主内容地标、路由焦点恢复、表格/卡片响应式替代、八类数据状态、capability 驱动操作显示、通用 401/403 页面、错误摘要、状态播报、模态焦点、帮助抽屉、未保存离开保护、刷新路由恢复、EN/ES/VI 英文回退和 `America/New_York` 时间格式化。

只使用现有项目模式和 `C311Provider`/mock，不修改 server 业务逻辑或数据库。使用 FE-00-GATE 的全部角色 fixture 做路由、capability、焦点和错误测试；响应式组件至少验证 360、767、768、1023、1024、1440、1920 CSS 像素。

退出条件：共享组件在全部目标视口中可操作，键盘焦点可见且顺序正确，路由改变后焦点进入主标题/主内容地标，模态焦点可封闭并返回，语言切换/刷新不会丢失服务器保存状态或有效输入。

### FE-02：公共门户与身份

实现主页、服务目录、帮助、登录、注册、忘记密码、重置密码、账户和我的请求入口；接入品牌/公共内容/上下文帮助、OIDC/SAML 入口、账户链接确认、联合注销、密码规则、无效/过期/单次使用 token 和安全通知状态。

必须验证：未知邮箱与已知邮箱使用相同的忘记密码公开响应；新 token 使旧 token 失效；改登录标识符前重新认证，成功后保留当前会话并撤销其他会话，冲突时值和会话不变；身份声明失败不改变账户集合。

所有请求通过 provider/mock；不保存秘密，不绕过后端会话和身份校验。完成匿名/已登录导航、身份失败恢复、内容失败、移动端导航和无障碍测试。

### FE-03：请求提交与草稿

实现服务类型、摘要、描述、请求者、地址/位置、附件入口、同意、动态字段、保存草稿和提交确认；覆盖匿名、已登录和员工协助三条路径。

实现客户端即时校验、服务端字段错误映射、幂等键、重复提交保护和单一进行中状态。验证 `201` 新建、`200` 等价重放、`422`、`401`、`403`、`IDEMPOTENCY_CONFLICT`、`VERSION_CONFLICT`；提交成功显示 `request_number` 和 `SUBMITTED`，来源渠道只能由服务端确定。

验证校验失败保留全部有效输入、焦点进入错误摘要/首个错误、草稿刷新和应用容器重启后仍可恢复；重复操作不能产生第二条业务写入。

### FE-04：附件与地图

实现最多 5 个附件、单个不超过 10 MiB、允许媒体类型和 1～120 字符文件名校验、移除、上传进度、下载/预览和失败提示。实现地址地理编码、规范地址、固定坐标、可移动标记、坐标确认和位置必填规则。

覆盖 `ADDRESS_NOT_FOUND`、地图 401、503、可重试错误和位置必填规则。无效附件必须先于请求创建被拒绝；地图失败必须保留表单；`MAP_API_TOKEN` 等秘密不得进入浏览器。地图标记坐标和文件选择必须可键盘操作。

### FE-05：查询、关系、注释与账户维护

实现匿名状态查询、我的请求、请求详情、公共状态和公共历史；编号或邮箱任一不匹配时必须返回相同的通用未找到结果和空详情。

增加请求关系界面和 adapter 契约，支持以下关系类型的查看、新增、解除和权限结果：`PRIMARY_REQUESTER`、`AFFECTED_RESIDENT`、`PROPERTY_OWNER`、`REPORTER`、`ORGANISATION_CONTACT`。验证一个且仅一个主请求者、关系组合唯一、`portal_visible`、`notify_status`、通知对象和审计结果。

实现选民注释的 append-only 行为，显示 actor、公共可见性和本地化时间；实现重新打开申请。实现个人资料、0～3 个电话、0～5 个地址、主要类别、首选语言、登录标识符、改密、忘记密码、重置密码和账户删除/匿名化结果入口。

### FE-06：员工队列与详情

实现按状态、服务类型、部门、地区、起源类、来源渠道、受让人、协作者、类别、创建范围和重复组过滤的队列，支持分页、排序、空结果、过滤保留和刷新恢复。

详情必须展示请求编号、摘要、公共状态、部门、位置、请求者、关系、受让人、协作者、提醒、附件、历史、审计和外部工单。根据当前 capability 和记录范围显示分诊、编辑、关系、协作者、重新分派、提醒、源类覆盖和审计入口。

覆盖服务代理、主管、部门经理、平台管理员、工作流设计者及跨部门/跨地区无权限场景；移动端使用卡片、受控横向滚动或精简列，文档视口不得横向溢出。

### FE-07：员工操作、批量处理与并发

实现分诊、主受让人/协作者管理、重新分派原因、状态转换、CivicWorks 状态、同题分组、批量更新/关闭、提醒创建/暂停/完成/取消和并发版本提交。

起源类覆盖必须要求非空理由；重新分派必须验证状态保留、前后受让人通知和审计。批量确认显示记录数和预期变化；批量校验/并发失败必须指出失败请求，且所有记录保持不变。

实现 `409 VERSION_CONFLICT` 恢复：展示当前版本，保留用户输入，提供重新加载和重新应用。CivicWorks 相关测试必须观察签名无效、旧版本、重复事件和重试后的单一 CRM 转换，不在浏览器伪造回调结果。

### FE-08：管理端

实现品牌字段、设备预览、显式发布、版本历史和回滚；公共字体选项必须包括 System Sans、Inter、Source Sans 3；品牌必须包含管理员提供的 logo alt text，并在发布前验证主色/强调色对比度。

实现主页、服务目录、帮助、页脚和条款内容的草稿/预览/发布/版本/回滚；帮助使用附录 15.4 的稳定 key 和本地化目录，打开后保留当前工作并返回调用焦点。

实现联系人类别添加/重命名/使用中保护；实现自定义字段定义、验证、选择值顺序、停用和历史值保留。所有可变资源使用版本和 `If-Match`；`VERSION_CONFLICT` 必须保留输入并提供恢复。HTML 只显示后端清理后的内容，发布前公共页面不得变化。

### FE-09：工作流、日历、邮件、报告、审计与导出

实现工作流创建、触发器、条件、动作、测试、激活/停用、版本和执行日志；显示 OAuth 成功、权限不足、无效客户端、过期 token 和临时不可用结果，秘密保存后必须遮蔽且不得进入前端。

实现 ICS 导入/导出、`UID` 原地更新、取消和导入摘要；验证 UTC 使用 `Z`、本地时间标识 `America/New_York`，未知取消 UID 被忽略并报告。

实现邮件模板选择/编辑/预览/发送；验证清理后的 HTML、421/451 可重试、550/553 终止、最多三次尝试、幂等 key 和终止失败记录。

实现五类最小报告、过滤、最多 20 列、一个分组、最多三列排序、保存/共享和 UTF-8 CSV。验证 CSV 头行、逗号分隔、RFC 4180 quoting、CRLF、ISO 8601 时间；联系人导出只包含 verified email 且 `opt_out=false`；共享报告范围不得超过创建者范围；导出处理分页、无效过滤、无效 page token 和 429。

实现审计过滤/导出和数据导出入口，审计只读且不可由前端修改。所有操作必须有进行中和最终成功/错误状态，空结果必须保留活动过滤器。

### FE-10：跨页面质量加固

逐页验证以下固定客户端矩阵：

| 客户端 | 最低版本/系统 | 视口 |
|---|---|---|
| Edge | 128，Windows 10+ | Desktop |
| Chrome | 128，Windows 10+ | Desktop |
| Firefox | 128，Windows 10 或 macOS 13+ | Desktop |
| Safari | 17，macOS 13+ | Desktop |
| Safari | 17，iOS/iPadOS | Mobile/Tablet |
| Chrome | 128，Android | Mobile/Tablet |

视口覆盖 360～767、768～1023、1024～1920，并执行 360、767、768、1023、1024、1440、1920 边界检查。每个客户端必须完成相同支持流程并产生等效服务器可见结果。

完成登录、提交、查询和员工更新四条 WCAG 2.2 AA 旅程；检查键盘路径、可见焦点、标签/错误关联、错误摘要、异步播报、模态焦点、路由焦点、文本状态、富文本清理、刷新和未保存离开。

加入两台受支持设备登录后读取同一账户、请求和服务器草稿的连续性测试；验证语言切换、可重试错误、版本冲突和刷新不丢失有效输入。输出响应式、无障碍、语言、浏览器、跨设备和刷新回归报告。

### FE-11：真实 API 联调与最终验收

按契约包逐步用真实 API 替换 mock，执行 mock/real parity，记录每项差异和处置。验证提交→分诊→分派→CivicWorks→回调→公共状态、关系链接/解除、注释、品牌发布/回滚、草稿刷新、附件、地图、身份、批量、提醒、邮件、工作流、ICS、报告、审计、导出、账户标识符和账户删除场景。

验证不同部门、地区和角色；浏览器刷新、两设备登录、应用容器重启、401/403、记录范围、审计、历史、持久化和外部 fixture 结果。不得伪造后端 seed、权限、回调、邮件、地图或外部系统结果。

### FE-11 最终合入门槛（必须全部满足）

1. **G2 API 就绪**：后端迁移、种子、API、权限和契约测试通过；前端 adapter parity 通过。
2. **G3 跨链路验收**：双方完成第 14 章公共操作及提交到履约再到公共状态更新的完整链路。
3. **第 14.1 浏览器观察面**：发布/回滚、刷新、身份、提交、附件、地图、关系、注释、提醒、分派、草稿、查询、批量、CivicWorks、邮件、报告/导出、标识符/重置、自定义字段全部有证据。
4. **第 14.2 回归面**：clean baseline、迁移 baseline、种子幂等、容器重启、角色/地区范围、API/浏览器/fixture/持久化结果一致。
5. 每个前端条款可追踪到实现、测试和截图/日志；已知限制必须有责任人、影响和发布/回滚说明。

以上五项是合取条件，任何一项未完成都不得提交最终合并 PR。
